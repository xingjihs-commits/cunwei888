# 34 - 故障演练手册

> 定期（每月 1 次）按本手册模拟故障，验证降级方案有效，避免真实故障时手忙脚乱。

## 34.1 演练目标

- 验证监控告警是否及时触发
- 验证降级方案是否生效
- 验证备份恢复是否可用
- 验证故障定位流程是否清晰
- 验证团队响应时间是否达标

## 34.2 演练场景清单

### 场景 1：submitFeedback 云函数挂了 30 分钟

**模拟方式**：
1. 在云开发控制台 → 云函数 → submitFeedback → 版本管理 → 切换到"故障版本"（人为引入 throw）
2. 或临时把 submitFeedback 权限设为"拒绝访问"

**预期表现**：
- 村民提交反映时 toast "网络异常，请重试"
- 错误率告警 5 分钟内触发
- logs 集合记录 frontend_error

**降级方案**：
- 在 docs/18-线上应急预案 中找到"核心云函数挂了"应急流程
- 临时引导村民通过"书记信箱"反映（绕过 submitFeedback）
- 紧急情况可让管理员在 admin/feedback-handle 手动录入

**验证点**：
- [ ] 错误告警 5min 内触达
- [ ] 村民至少能看到 toast，不是空白卡死
- [ ] 修复后 5min 内业务恢复

---

### 场景 2：数据库 records 集合被误删

**模拟方式**：
1. 备份当前 records 集合
2. 清空 records 集合

**预期表现**：
- getHomeData 不受影响（首页不依赖 records）
- getMyFeedback 返回空列表，EmptyState 组件显示"暂无反映"
- getDashboardStats 返回 0 工单
- admin/feedback-list 显示"暂无工单"

**降级方案**：
1. 立即从备份恢复 records 集合
2. 通知所有管理员暂停工单处理
3. 故障期间引导村民通过书记信箱反映

**验证点**：
- [ ] 备份恢复在 30min 内完成
- [ ] 恢复后数据完整性 100%
- [ ] 管理员和村民功能恢复正常

---

### 场景 3：sendSubscribeMessage 全部失败

**模拟方式**：
1. 临时清空 module_config.subscribe_templates.templates
2. 或暂停云函数部署

**预期表现**：
- 工单提交/状态变更/派单均能成功，但通知发送失败
- logs 集合记录"模板未配置，已跳过"
- 村民收不到微信订阅消息

**降级方案**：
- 派单通知 → 责任人在 admin/my-dispatched 主动刷新
- 状态变更 → 村民在 my-feedback 主动刷新
- 超时催办 → sendOverdueReminder 仍能写入 isOverdue 标记，但通知发送失败

**验证点**：
- [ ] 业务流程不阻断
- [ ] 通知失败不导致工单丢失
- [ ] 模板配置恢复后通知恢复

---

### 场景 4：内容安全 openapi 权限失效

**模拟方式**：
1. 微信公众平台 → 开发管理 → 接口设置 → 关闭 msgSecCheck

**预期表现**：
- checkContentSecurity catch 中返回 'review'，所有内容入 audit_queue
- 提交反映/随手拍等返回"内容正在审核中"提示
- audit_queue 集合数据激增

**降级方案**：
- 管理员在 admin/audit-queue 人工复审
- 故障期间提交的内容全部入复审队列
- 恢复 openapi 后正常

**验证点**：
- [ ] fail-closed 生效，违规内容不绕过
- [ ] audit_queue 集合正确接收
- [ ] 复审流程闭环

---

### 场景 5：定时触发器配置失效

**模拟方式**：
1. 云开发控制台 → 云函数 → sendOverdueReminder → 触发器 → 暂停

**预期表现**：
- 超时工单不会被标记 isOverdue
- 不会被通知责任人
- 超时升级通知不会触发

**降级方案**：
- 管理员在 admin/dashboard 手动查看 handleDeadline < now 且 status in [待处理, 处理中] 的工单
- 手动调用 sendOverdueReminder 云函数测试入口

**验证点**：
- [ ] 48h 内监控告警触发"定时器未执行"
- [ ] 管理员能手动触发催办
- [ ] 定时器恢复后正常工作

---

### 场景 6：管理员 openid 被误撤销

**模拟方式**：
1. 在 admins 集合将自己的 enabled 改为 false

**预期表现**：
- App.vue onShow 中 refreshUserInfo 5min 内拉到最新，isAdmin 变为 false
- 进入 admin/* 页面被 useAdminGuard 拦截
- toast "无管理员权限" + navigateBack

**降级方案**：
- 联系其他管理员重新启用
- 紧急情况在云开发控制台手工修改 admins 集合

**验证点**：
- [ ] 客户端 5min 内同步权限变化
- [ ] 云函数仍能拒绝（即使客户端漏判）
- [ ] 管理员能恢复

---

### 场景 7：图片上传全部失败

**模拟方式**：
1. 临时把云存储权限改为"私有"

**预期表现**：
- uploadImages 全部失败
- cleanupFileIDs 清理已上传文件
- 提交反映/随手拍/任务进度 toast"图片上传失败"

**降级方案**：
- 引导用户先提交文字描述，后补图片
- 紧急情况可让管理员代为上传

**验证点**：
- [ ] 失败时不产生孤儿文件
- [ ] 用户能看到清晰错误提示
- [ ] 恢复后图片上传正常

---

### 场景 8：网络断网 30 秒

**模拟方式**：
1. 手机开启飞行模式 30 秒后关闭

**预期表现**：
- App.vue onNetworkStatusChange 触发 toast "当前网络不可用"
- 用户提交操作 toast "网络异常，请重试"
- 表单草稿已保存，恢复网络后能继续

**验证点**：
- [ ] 网络监听及时触发
- [ ] 草稿恢复有效
- [ ] 恢复网络后能正常提交
