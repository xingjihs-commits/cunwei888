# 30 - 运维手册

> 本文档面向项目运维人员，涵盖日常运维、监控、故障处理、备份恢复。

## 30.1 日常运维任务

### 30.1.1 每日检查
- [ ] 查看云开发控制台 → 监控告警 → 是否有错误率超 1% 的云函数
- [ ] 查看 `logs` 集合 → 是否有 `action: 'frontend_error'` 或 `action: 'subscribe_message_skip'`
- [ ] 查看 `audit_queue` 集合 → 是否有 `待复审` 内容需处理
- [ ] 查看 `reports` 集合 → 是否有举报待处理

### 30.1.2 每周检查
- [ ] 查看 `records` 集合 → `isOverdue: true` 且 `status` 在 `['待处理','处理中','已派单']` 的工单，跟进责任人
- [ ] 查看 `rectifications` 集合 → `status: '整改中'` 的整改记录，督促完成
- [ ] 查看 `secretary_mails` 集合 → `status: '待处理'` 超过 3 天的信件，提醒书记查阅

### 30.1.3 每月任务
- [ ] 调用 `generatePerformanceReport` 生成上月考核统计
- [ ] 调用 `generateUpperReport` 生成上月对上汇报
- [ ] 备份数据库（按 docs/04 数据备份与换届交接制度）

## 30.2 监控指标

### 30.2.1 云函数监控
在云开发控制台 → 监控告警，配置以下指标的告警：
- 错误率 > 5% 持续 5 分钟
- P95 响应时间 > 5 秒 持续 10 分钟
- 调用量突增/突降 > 50%

重点关注的云函数：
- `submitFeedback`：村民提交反映的核心，故障会让村民无法反映
- `getHomeData`：首页聚合，故障会让首页空白
- `getRecordDetail`：详情查询，故障会让责任人看不到工单
- `sendSubscribeMessage`：通知发送，故障会让责任人和村民收不到通知
- `sendOverdueReminder`（定时器）：超时催办，故障会让超时工单无人管

### 30.2.2 数据库监控
- `records` 集合：单日新增 > 100 条为异常（小村不会有这么多反映）
- `audit_queue` 集合：单日新增 > 10 条为异常（违规内容激增）
- `reports` 集合：单日新增 > 5 条为异常（可能有人在刷举报）
- `logs` 集合：单日 `frontend_error` > 50 条为异常

## 30.3 故障处理流程

### 30.3.1 故障等级
| 等级 | 影响 | 响应时间 |
|------|------|---------|
| P0 | 村民无法提交反映/责任人无法查看工单 | 30 分钟内响应 |
| P1 | 通知发送失败/某些 admin 页面打不开 | 2 小时内响应 |
| P2 | 个别详情页报错/统计不准 | 当日响应 |
| P3 | 体验问题/小 bug | 次日响应 |

### 30.3.2 故障定位步骤

1. **收集信息**：用户描述 + 截图 + 操作时间 + openid
2. **查 logs 集合**：
   ```js
   db.collection('logs').where({
     createTime: _.gte(new Date(Date.now() - 30 * 60 * 1000))
   }).orderBy('createTime', 'desc').limit(50).get()
   ```
3. **查 cloudfunctions 日志**：在云开发控制台 → 云函数 → 日志，按时间筛选
4. **复现问题**：用故障用户的 openid 在测试环境复现
5. **修复**：改代码 → 上传部署 → 验证 → 通知用户

### 30.3.3 常见故障处理

| 现象 | 可能原因 | 处理方式 |
|------|---------|---------|
| 首页加载失败 | module_config 缺 village_info | 在 module_config 集合补 village_info 配置 |
| 反映提交后无派单 | dispatchMap 未配置或 type 不匹配 | 在 dispatch-config 页面为该 type 配置责任人 openid |
| 通知没收到 | 订阅模板未配置或用户未授权 | module_config.subscribe_templates 配置真实模板 ID；用户重新点击触发订阅授权 |
| 管理员页面打不开 | 当前 openid 不在 admins 集合 | 在 admins 集合添加 `{_openid, enabled: true}` |
| 内容安全一直拒绝 | openapi 权限未开通 | 微信公众平台 → 开发管理 → 接口设置 → 开通 msgSecCheck/imgSecCheck |
| 图片上传失败 | 云存储配额满 / 权限 | 清理过期文件 / 检查云存储权限 |
| 工单状态错乱 | 老英文数据未迁移 | 调用 migrateStatusEnum 云函数 |

## 30.4 数据备份与恢复

### 30.4.1 备份策略
- **每日自动备份**：云开发数据库自动每日备份，保留 7 天
- **每月手动备份**：月底在云开发控制台 → 数据库 → 导出全量 JSON，存到本地或对象存储
- **重大变更前备份**：升级代码、迁移数据前必须先备份

### 30.4.2 备份内容
| 集合 | 备份方式 | 频率 |
|------|---------|------|
| users | JSON 导出 | 每月 |
| records | JSON 导出 | 每周（核心数据） |
| tasks | JSON 导出 | 每月 |
| votes | JSON 导出 | 每月 |
| meetings | JSON 导出 | 每月 |
| broadcasts | JSON 导出 | 每月 |
| finance_reports | JSON 导出 | 每月（敏感） |
| module_config | JSON 导出 | 每次配置变更后 |
| admins | JSON 导出 | 每月（敏感） |
| logs | 不需备份 | - |
| audit_queue | 不需备份 | - |

### 30.4.3 恢复流程
1. 在云开发控制台 → 数据库 → 选择集合 → 导入 JSON
2. 选择备份的 JSON 文件 → 确认导入
3. 验证数据完整性
4. 如有冲突 _id，先删除当前集合再导入

## 30.5 换届交接

按 docs/04 数据备份与换届交接制度：
1. 旧一届管理员在 admins 集合 enabled 改为 false
2. 新一届管理员添加到 admins 集合
3. 在 team_members 集合更新班子成员
4. 在 module_config.feedback.dispatchMap 更新责任人 openid
5. 在 module_config.village_info 更新村值班电话

## 30.6 安全审计

### 30.6.1 月度审计
- 查询 `logs` 集合，统计各管理员操作频次
- 查询 `admins` 集合，确认是否有不应有管理员
- 查询 `users` 集合 verifyStatus 字段，确认认证审核是否合规
- 查询 `audit_queue` 集合，确认违规内容是否及时处理

### 30.6.2 异常处理
- 发现违规管理员：在 admins 集合将其 enabled 改为 false
- 发现违规村民：在 `reports` 集合 status 改为 `违规确认`，累计 3 次自动限制投票功能
- 发现数据被篡改：从备份恢复，查 logs 追溯责任人

## 30.8 版本回滚

云函数回滚：
1. 云开发控制台 → 云函数 → 选择函数 → 版本管理
2. 回滚到上一个稳定版本

代码回滚：
1. Git 回滚到上一个 tag
2. 重新 `npm run build:mp-weixin`
3. 在微信开发者工具上传

数据库回滚：
1. 云开发控制台 → 数据库 → 备份恢复
2. 选择最近备份 → 恢复

## 30.10 文档维护

本项目通过脚本防止「文档与代码漂移」，规则如下：

1. 每次改动代码（新增/删除 页面、云函数、组件、文档）后，运行 `npm run gen:doc`
   自动重新生成 `docs/00-代码结构清单.md`。
2. 提交前运行 `npm run check:doc`，校验 README、docs/00 的数量与清单是否与实际代码一致。
3. 如果 `check:doc` 报错，先修正文档（或先 `gen:doc` 再同步 README 数量），再提交。
4. 为什么这样做：README / docs/00 里的「页面数、云函数数、清单」曾多次与代码不一致
   （例如页面 62→63、云函数 85→88），人工维护易漏。用「脚本生成 + 校验」把文档一致性
   变成可执行的门禁，避免漂移复发。

> 分类口径：云函数固定按 10 类归并（见 `scripts/gen-structure.js` 的 `CLOUD_CLASSIFY`）；
> 新增云函数必须登记到对应分类，否则 `check:doc` 会报「未登记」。
