# 29 - 二次开发指南

> 本文档面向后续接手本项目的开发者，说明常见二次开发场景需要改动的位置。

## 29.1 新增一个事项类型（如"医疗健康"）

**只改配置，不改代码**：

1. 在云开发控制台 → `module_config` 集合 → 找到 `moduleKey: 'feedback'` 记录
2. 编辑 `feedbackTypes` 数组，新增：
   ```json
   { "key": "医疗健康", "name": "医疗健康", "icon": "🏥" }
   ```
3. 编辑 `dispatchMap`，新增：
   ```json
   "医疗健康": { "openid": "xxx", "name": "村医张三", "duty": "管医疗健康" }
   ```
4. 在 admin/dispatch-config 页面会自动出现"医疗健康"配置项
5. 老百姓在 feedback.vue 选择"医疗健康"提交后，自动派给村医

**注意**：`store/config.js` 的默认 `feedbackTypes` 数组也要加上（兜底用，云端未配置时显示）。修改 `state.feedbackTypes` 数组追加一项即可。

## 29.2 新增一个责任人

**完全在 admin 页面操作**：

1. 进入"内容发布 → 发布村务新闻/任务"等页面，可填入责任人姓名
2. 进入"分配地图"配置页，为某类型工单指定责任人 openid
3. 责任人 openid 获取方式：
   - 让该责任人登录小程序
   - 在云开发控制台 `users` 集合查 `_openid` 字段

## 29.3 新增一个村组

**不需要改代码**：
- 村民在 verify.vue 填写 villageGroup 时自由输入
- 看板按 villageGroup 维度分组统计时自动支持

## 29.4 新增一个订阅消息模板

1. 在微信公众平台 → 订阅消息 → 申请模板，获取模板 ID
2. 在云开发控制台 → `module_config` 集合 → 找到 `moduleKey: 'subscribe_templates'` 记录
3. 编辑 `templates` 字段，加入新的 key-value：
   ```json
   { "新模板": "tmpl_xxxxxxxxxxxx" }
   ```
4. 在 `cloudfunctions/sendSubscribeMessage/index.js` 的 `buildMessageData` 函数中追加该 type 的模板数据结构
5. 在调用 `sendSubscribeMessage` 的云函数中传 `type: '新模板'`

## 29.5 新增一个页面

**改 1 处配置 + 创建 1 个文件**：

1. 在 `pages.json` 的 `pages` 数组中添加路由：
   ```json
   {
     "path": "pages/xxx/yyy",
     "style": { "navigationBarTitleText": "页面标题" }
   }
   ```
2. 创建 `pages/xxx/yyy.vue` 文件
3. 如需在 mine.vue 菜单中暴露，编辑 mine.vue 添加 menu-item

## 29.6 新增一个云函数

1. 在 `cloudfunctions/` 下创建目录，如 `cloudfunctions/myNewFunc/`
2. 创建 `index.js`、`package.json`：
   ```json
   {
     "name": "myNewFunc",
     "version": "1.0.0",
     "main": "index.js",
     "dependencies": { "wx-server-sdk": "~2.6.3" }
   }
   ```
3. 编写 `index.js`（≤150 行，统一返回 `{success, message, data}`）
4. 鉴权：
   - 公开查询：不需 checkAdmin
   - 管理员操作：开头加 `const isAdmin = await checkAdmin(OPENID); if (!isAdmin) return { success: false, message: '无权限' }`
   - 用户操作自己数据：用 `_openid: OPENID` 过滤
5. 内容安全：如写入用户文本/图片，调用 `checkContentSecurity` / `checkImageSecurity`
6. 在微信开发者工具右键云函数目录 → "上传并部署"

## 29.7 换一个村使用

**改配置即可，不改代码**：

1. 替换 `manifest.json` 中的 AppID 和 ext.cloudEnv
2. 在新村的云开发控制台运行 `initDatabase` 云函数（自动建表 + 初始数据）
3. 在 `module_config` 集合配置：
   - `village_info`：村名、村值班电话、ICP 备案号、紧急电话
   - `subscribe_templates`：7 个订阅消息模板 ID
   - `feedback.dispatchMap`：各类型责任人 openid
4. 在 `admins` 集合添加管理员 openid
5. 上线前替换 `initDatabase/initData.js` 中的占位电话为真实电话

## 29.8 换一个云环境

**改 1 处配置**：

1. `manifest.json` 的 `mp-weixin.ext.cloudEnv` 改为新环境 ID
2. `App.vue` 兜底 envId 可保持 `village-bridge-prod`（会被 ext 覆盖）
3. 重新部署所有云函数到新环境

## 29.9 新增一个页面 tab

1. 在 `pages.json` 的 `tabBar.list` 中添加 tab 配置
2. 准备 `static/tabbar/xxx.png` 和 `xxx-active.png`（建议 81x81 PNG）
3. 如该 tab 指向新页面，按"29.5 新增页面"操作

## 29.10 新增适老化大字号模式（未来功能）

1. 在 `uni.scss` 中已经定义 `$font-scale: 1.0`
2. 在 `App.vue` 的 onLaunch 中读取 `uni.getStorageSync('fontScale')`，写入全局 CSS 变量
3. 在 mine.vue 增加"适老化设置"入口，让用户选 1.0/1.2/1.4
4. 各页面用 `rpx` 配合 CSS 变量动态缩放

## 29.12 测试与上线流程

1. **本地开发**：`npm run dev:mp-weixin` 启动 uni-app 编译，在微信开发者工具中打开
2. **云函数部署**：在微信开发者工具中右键 `cloudfunctions/` 下每个目录 → "上传并部署：云端安装依赖"
3. **数据初始化**：部署 `initDatabase` 后通过云开发控制台测试入口调用一次
4. **数据迁移**（如升级）：调用 `migrateStatusEnum` 一次（先 dryRun=true）
5. **管理员开通**：在 `admins` 集合添加 `{ _openid, enabled: true }`
6. **预览测试**：微信开发者工具 → "预览" → 手机扫码体验
7. **审核**：按 docs/17 微信审核预检清单 → 上传代码 → 提交审核
8. **发布**：审核通过后 → 微信公众平台 → 发布

## 29.13 故障排查

| 现象 | 排查方向 |
|------|---------|
| 首页空白 | 检查 module_config.village_info 是否配置 |
| 反映提交后无派单 | 检查 module_config.feedback.dispatchMap 是否配置责任人 openid |
| 管理员页面打不开 | 检查 admins 集合是否有当前 openid |
| 通知没收到 | 检查 module_config.subscribe_templates.templates 是否填了真实模板 ID |
| 图片上传失败 | 检查云存储权限、网络 |
| 内容安全不生效 | 检查是否开通 msgSecCheck/imgSecCheck openapi 权限 |
| 工单状态不正确 | 调用 migrateStatusEnum 转换老英文数据 |
