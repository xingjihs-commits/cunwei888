## 2. 媒体复审自动发布（audit_queue 消费端）

### 现状（已核实）
- 入队链路完整：`publishLeaderContent`（`leader_content`，含视频 → `published:false`）、
  `publishBroadcast`（`broadcasts`，含音频 → `published:false`，且跳过群发）。
- 缺口：`reviewContent/index.js:40` 复审通过只更新 `records` 集合，而媒体记录不在 `records` →
  更新失败落入 catch；媒体 `published` 永远 `false`；广播不补群发。
- 复审通过未回写原 `audit_queue` 条 `status` → 队列条残留、可重复复审。
- 图片复审（无 `recordId`）前端仅提示"到控制台手工删除"。

### 方案
1. 抽 `cloudfunctions/common/mediaReview.js`：按 `audit_queue` 条的 `collection`/`recordId` 分发：
   - `leader_content` → `published:true`
   - `broadcasts` → `published:true` + 复用被跳过的群发逻辑（先读懂原文再决定抽取/调用）
   - 未知 `collection` → 记日志，不误改。
2. 改造 `reviewContent`：通过时调用 `mediaReview`；同时把对应 `audit_queue` 条 `status` 置"已处理"（按 `recordId`/`_id` 精确匹配）。
3. 前端 `pages/admin/audit-queue.vue`：补齐图片复审路径（标记队列条状态），去掉"手工删除"提示。

### 验收
- 云函数 `node --check` 通过。
- 构造含视频的 `leader_content` → 复审通过 → `published` 变 `true` 且列表可见。
- 音频场景确认群发触发；重复复审无副作用。

### 风险
- 群发逻辑抽取需严格对照原文。
- 涉及真实云数据库写入，**需在测试环境验证，不污染生产**。

## 3. 适老化字号倍数全局生效（方案 A）

### 现状（已核实）
- 基础设施齐全：`utils/accessibility.js` 单例（fontScale 1.0/1.2/1.4 + highContrast 等）、
  `App.vue:23 loadA11y()`、设置页 `pages/settings/accessibility.vue`。
- 但 `a11y.fontScale` 全仓仅 `components/BigButton.vue:46` 一处消费 → 倍数对全站不生效。

### 实施记录（已完成，方案 B）
方案 A（`calc(<base>rpx * var(--vb-fs, 1))`）经真机验证**失败**：微信 WXSS 不支持 `calc` 内 `var()` 参与长度乘法，报 `unexpected \`。
实际采用 **方案 B：rem + `<page-meta root-font-size>`**：
1. `uni.scss` 字号改 rem（基准 `32rpx = 1rem`）。
2. `composables/useA11y.js` 导出 `useRootFontSize()`：`rootFontSize(px) = (屏宽/750)*32*fontScale`。
3. **全部 70 个页面**模板首位注入 `<page-meta :root-font-size="rootFontSize" />`（脚本 `scripts/apply-a11y-pagemeta.js`）。
4. 期间修复既有 bug：中文 CSS 类名（`.tag-财务`/`.u-普通`）被压缩转义为 `\8d22`，微信 WXSS 报 `unexpected \`
   → 改为英文类名（`utils/format.js: urgentTagClass`、`pages/index/index.vue: noticeTagClass`）。

### 遗留：硬编码 rpx 字号（不随倍数缩放）
约 51 处 `font-size: <N>rpx` 直接写字号，不受 page-meta 基准影响；后续替换为 `$font-*`（rem）变量以全站一致。

### 验收（已通过）
- 开发者工具：设置页切 1.0/1.2/1.4 → 字号随之变化；`pages/index` 不再报 WXSS 编译错误。
