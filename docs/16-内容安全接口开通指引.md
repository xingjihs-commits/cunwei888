# 第十六部分：内容安全接口开通指引

**适用对象**：技术对接人、内容审核员
**前置条件**：小程序已注册

---

## 16.1 接口说明

### 16.1.1 msgSecCheck（文本检测）

| 项目 | 说明 |
|------|------|
| 功能 | 检测文本是否含违规内容（政治、色情、暴恐、辱骂等） |
| 调用方式 | `cloud.openapi.security.msgSecCheck` |
| 文本长度限制 | 单次≤2000字 |
| 每日调用限额 | 100万次（足够使用） |
| 计费 | 免费 |

### 16.1.2 imgSecCheck（图片检测）

| 项目 | 说明 |
|------|------|
| 功能 | 检测图片是否含违规内容 |
| 调用方式 | `cloud.openapi.security.imgSecCheck` |
| 图片格式 | jpg、png、bmp、gif |
| 图片大小限制 | 单张≤1.5MB |
| 每日调用限额 | 100万次 |
| 计费 | 免费 |

### 16.1.3 返回结果三种状态

| 状态 | errcode | 处理方式 |
|------|---------|---------|
| pass（通过） | 0 | 内容正常，可发布 |
| review（疑似违规） | 87014 | 进入人工复审队列 |
| risky（确认违规） | 87013 | 直接拒绝，通知用户 |

**本平台处理逻辑**：
- pass：写入数据库
- review：写入audit_queue集合，通知管理员复审
- risky：直接拒绝，返回错误提示

### 16.1.4 支持的文本长度与图片格式

| 类型 | 限制 |
|------|------|
| 文本单次 | ≤2000字（建议≤500字分批检测） |
| 图片单张 | ≤1.5MB |
| 图片格式 | jpg/png/bmp/gif |
| 图片尺寸 | 建议≤1080px |

## 16.2 开通步骤

### 16.2.1 登录微信公众平台

1. 打开 https://mp.weixin.qq.com
2. 管理员扫码登录

1. 点击「开通」按钮
2. 阅读接口使用规范
3. 确认开通

### 16.2.4 审核时间与注意事项

| 项目 | 说明 |
|------|------|
| 审核时间 | 即时开通 |
| 是否需要资质 | 不需要额外资质 |
| 注意事项 | 1.不可滥用（每日≤100万次）；2.不可绕过检测；3.需配合人工复审 |

## 16.3 代码集成

### 16.3.1 checkAdmin.js内容安全检测代码

**文件位置**：`cloudfunctions/common/checkAdmin.js`

代码已包含完整的内容安全检测函数：

```javascript
// 文本内容安全检测
module.exports.checkContentSecurity = async function (content, openid) {
  try {
    const res = await cloud.openapi.security.msgSecCheck({
      content: content,
      openid: openid,
      scene: 1,  // 1=资料 2=评论 3=论坛 4=社交日志
      version: 2
    })
    return res.errcode === 0  // 0=通过
  } catch (err) {
    // 测试环境无权限调用时，默认通过
    console.warn('内容安全检测跳过:', err.errMsg)
    return true
  }
}

// 图片内容安全检测
module.exports.checkImageSecurity = async function (fileID) {
  try {
    const res = await cloud.openapi.security.imgSecCheck({
      media: { contentType: 'image/jpeg', value: fileID }
    })
    return res.errcode === 0
  } catch (err) {
    console.warn('图片安全检测跳过:', err.errMsg)
    return true
  }
}
```

### 16.3.2 文本检测调用方式

在提交工单/随手拍/信件的云函数中调用：

```javascript
const checkAdmin = require('../common/checkAdmin')
const isSafe = await checkAdmin.checkContentSecurity(content, OPENID)
if (!isSafe) {
  return { success: false, message: '内容包含违规信息，请修改后重试' }
}
```

**已集成的云函数**：
- submitFeedback（反映提交）
- submitSnapshot（随手拍提交）
- submitSecretaryMail（书记信箱）
- publishLostFound（失物招领）

### 16.3.3 图片检测调用方式

```javascript
const checkAdmin = require('../common/checkAdmin')
const isImageSafe = await checkAdmin.checkImageSecurity(fileID)
if (!isImageSafe) {

```

### 16.3.4 审核不通过时的用户提示文案

| 场景 | 提示文案 |
|------|---------|
| 文本违规 | "内容包含违规信息，请修改后重试" |
| 图片违规 | "图片包含违规内容，请更换后重试" |
| 疑似违规 | "您的提交已收到，正在审核中，请耐心等待" |

### 16.3.5 疑似违规进入人工复审队列的逻辑

当msgSecCheck返回review状态时，写入audit_queue集合：

```javascript
// 在checkContentSecurity中增强（如需复审入库）：
if (res.errcode === 87014) {
  // 疑似违规，写入复审队列
  await db.collection('audit_queue').add({
    data: {
      recordId: recordId,
      type: 'text',
      content: content,
      status: 'pending',
      createTime: new Date()
    }
  })
  return 'review'  // 返回复审状态
}
```

### 16.3.6 审核超时的处理方式

- 复审时效：24小时内
- 超时未复审：内容暂不公示，但保留记录
- 超时3天：自动驳回，通知用户

## 16.4 人工复审流程

### 16.4.1 reviewContent云函数使用方法

**调用方式**：
```javascript
// 复审通过
callFunction('reviewContent', {
  recordId: 'xxx',
  passed: true,
  reason: ''
})

// 复审驳回
callFunction('reviewContent', {
  recordId: 'xxx',
  passed: false,
  reason: '内容涉及人身攻击'
})
```

### 16.4.2 管理端查看待复审内容

1. 管理员登录小程序
2. 「我的」→「管理员功能」
3. 查看audit_queue集合中status=pending的记录
4. 逐条审核

### 16.4.3 复审通过/拒绝操作步骤

1. 查看内容
2. 点击「通过」或「驳回」
3. 驳回需填写原因
4. 提交复审结果
5. 系统自动：
   - 通过：更新原记录status为公示
   - 驳回：更新原记录status为rejected，通知用户

### 16.4.4 复审记录留痕

复审结果写入audit_queue集合：
```json
{
  "recordId": "xxx",
  "reviewer": "复审人openid",
  "passed": true/false,
  "reason": "驳回原因",
  "reviewTime": "2026-01-01"
}
```

同时写入logs集合作为操作日志。

### 16.4.5 复审时效要求

| 内容类型 | 复审时效 |
|---------|---------|
| 普通工单 | 24小时内 |
| 紧急工单 | 2小时内 |
| 疑似重大违规 | 立即上报公安机关 |

## 16.5 合规要求

### 16.5.1 审核通过的内容保存期限

| 内容类型 | 保存期限 |
|---------|---------|
| 已公示工单 | 3年 |
| 已公示随手拍 | 1年 |
| 操作日志 | 3年 |
| 复审记录 | 3年 |
| 违规内容记录 | 3年（含处理结果） |

**合规要求**：保存不少于60天（法规要求），本平台保留3年（治理留痕需要）。

### 16.5.2 审核日志记录要求

每次内容安全检测+人工复审，需记录：
- 检测时间
- 检测对象（recordId）
- 检测结果（pass/review/risky）
- 复审人（如适用）
- 复审结果（通过/驳回）
- 处理动作

### 16.5.3 用户申诉机制

| 渠道 | 方式 |
|------|------|
| 小程序内 | 「我的」→「个人信息」→联系村委 |
| 电话 | 村委值班电话 |
| 上级 | 街道办/12345 |

### 16.5.4 违规内容处理流程

1. 系统检测违规 → 自动拒绝
2. 疑似违规 → 进入复审队列
3. 管理员复审 → 通过或驳回
4. 严重违规 → 立即删除+报送公安机关
5. 重复违规用户 → 限制使用

### 16.5.5 向网信部门报告的义务

| 情况 | 报告时限 |
|------|---------|
| 一般违规 | 24小时内记录 |
| 严重违规（涉政、涉恐） | 立即上报网信办（12377） |
| 违法内容 | 立即报送公安机关（110） |
