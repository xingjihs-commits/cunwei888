# 28 - 架构分层说明

> 本文档定义"村务连心桥"项目的分层架构与职责边界，所有代码改动需遵守此规范。

## 28.1 分层架构

```
┌──────────────────────────────────────────────┐
│  视图层（pages/）                            │  ← Vue 组件
│  职责：渲染 UI、用户交互、表单校验、错误态展示  │
├──────────────────────────────────────────────┤
│  应用层（store/、composables/）               │  ← Pinia store / 组合式函数
│  职责：状态管理、权限拦截、跨页面共享状态      │
├──────────────────────────────────────────────┤
│  接口层（utils/request.js）                  │  ← 云函数调用封装
│  职责：统一 callFunction、错误处理、超时、    │
│       锁、上传图片、清理孤儿文件              │
├──────────────────────────────────────────────┤
│  云函数层（cloudfunctions/）                 │  ← wx-server-sdk
│  职责：业务逻辑、数据校验、鉴权、内容安全、    │
│       数据库读写、调用其他云函数              │
├──────────────────────────────────────────────┤
│  数据层（云开发数据库 / 云存储）              │  ← db.collection() / cloud.uploadFile()
│  职责：数据持久化、文件存储                    │
├──────────────────────────────────────────────┤
│  基础设施层（common/、配置、wx.cloud）        │  ← 公共模块、环境、SDK
│  职责：常量、共用工具、云开发 SDK、消息推送    │
└──────────────────────────────────────────────┘
```

## 28.2 跨层调用规则

### ✅ 允许的调用方向（上层→下层）
- 视图层 → 应用层（如 `userStore.isAdmin`）
- 视图层 → 接口层（如 `callFunction('xxx', {...})`）
- 应用层 → 接口层（如 `userStore.refreshUserInfo()` 调用 callFunction）
- 接口层 → 云函数层（如 `wx.cloud.callFunction`）
- 云函数层 → 数据层（如 `db.collection('records').add()`）
- 云函数层 → 基础设施层（如 `require('../common/checkAdmin')`）
- 云函数层 → 云函数层（如 `submitFeedback` 调 `sendDispatchNotice`，合理）

### ❌ 禁止的调用方向
- 视图层直接读写数据库（除非特殊场景如导出 CSV）
- 视图层直接 `wx.cloud.callFunction`（必须走 utils/request.js 的 callFunction 封装）
- 应用层（store）直接操作数据库
- 云函数直接读写 storage（storage 是视图层职责）
- 云函数互相循环调用（A 调 B，B 又调 A）

### ⚠️ 特殊例外
- `pages/admin/dashboard.vue` 用 `wx.cloud.downloadFile` 下载导出的 CSV 报表
  - 原因：下载文件是单次操作，封装到 utils 反而过度抽象
  - 允许保留

## 28.3 文件目录职责

| 目录 | 职责 | 文件命名规则 |
|------|------|--------------|
| `pages/` | 视图层，每个文件一个页面 | kebab-case，如 `feedback-detail.vue` |
| `components/` | 可复用组件 | PascalCase，如 `BigButton.vue` |
| `composables/` | 组合式函数 | use前缀，如 `useAdminGuard.js` |
| `store/` | Pinia store（应用层状态） | 业务名，如 `user.js`、`config.js` |
| `utils/` | 工具函数（接口层 + 通用工具） | 功能名，如 `request.js`、`format.js` |
| `cloudfunctions/` | 云函数（每个函数一个目录） | kebab-case，如 `submit-feedback`（当前为 camelCase 兼容历史） |
| `cloudfunctions/common/` | 云函数公共模块（被 require） | 不部署，仅 require |
| `static/` | 静态资源（图片、图标） | kebab-case |
| `docs/` | 项目文档 | `NN-标题.md`，NN 为编号 |

## 28.4 返回格式统一

所有云函数返回值必须遵守：
```js
{
  success: boolean,    // 是否成功
  message: string,     // 提示信息（错误时给用户看）
  data: any,           // 业务数据（查询时返回，写入时通常不返回）
  total?: number,      // 分页查询时的总数
  page?: number,
  pageSize?: number
}
```

**禁止**：
- 直接 `return 裸数据`（如 `return list`）
- 用 `code: 0/1` 而非 `success: true/false`
- 用 `msg` 而非 `message`

## 28.5 错误处理统一

### 视图层
- `callFunction` 失败时由 utils/request.js 统一 toast 提示
- 业务逻辑错误（`success: false`）也由 request.js 处理
- 页面只需要处理"加载中"和"错误态 + 重试"两种 UI 状态

### 云函数层
- 所有云函数必须 `try { ... } catch (err) { console.error(...); return { success: false, message: '操作失败' } }`
- 不要 throw 让调用方处理
- 关键错误写入 `logs` 集合

## 28.6 配置管理

| 类型 | 存储位置 | 说明 |
|------|---------|------|
| AppID、云环境 ID | `manifest.json` ext 配置 | 上线前手工替换 |
| 村名、电话、ICP | 云开发 `module_config` 集合 | 动态加载，配置驱动 |
| 订阅消息模板 ID | `module_config.subscribe_templates` | 动态加载 |
| 反馈类型/责任人映射 | `module_config.feedback.dispatchMap` | 管理员在 dispatch-config 页面配置 |
| 模块开关 | `module_config.<moduleKey>.enabled` | 管理员在 module-config 页面配置 |
| 状态/类型枚举 | `cloudfunctions/common/constants.js` | 代码常量，需改代码 |
| 字号/颜色/间距 | `uni.scss` | 设计变量 |

## 28.7 鉴权边界

| 云函数 | 鉴权方式 |
|--------|---------|
| `submit*`（村民提交） | 不需鉴权，但要内容安全 |
| `publish*`/`create*`（管理员发布） | 必须 `checkAdmin(OPENID)` |
| `update*`（更新数据） | `assigneeOpenid === OPENID \|\| checkAdmin(OPENID)` |
| `getMy*`（查询自己数据） | 用 OPENID 过滤，不需 checkAdmin |
| `get*List`/`get*Detail`（公开查询） | 公开内容不需鉴权 |
| `admin/*` 页面 | onMounted 必须 `useAdminGuard().ensureAdmin()` |

## 28.9 命名规范

- **云函数**：camelCase（如 `submitFeedback`），与微信云开发约定一致
- **页面**：kebab-case（如 `feedback-detail.vue`）
- **组件**：PascalCase（如 `BigButton.vue`）
- **变量**：camelCase（如 `recordId`）
- **常量**：UPPER_SNAKE_CASE（如 `RECORD_STATUS`）
- **集合名**：snake_case（如 `audit_queue`、`module_config`）
- **字段名**：camelCase（如 `createTime`、`assigneeOpenid`）

## 28.10 文件大小限制

- 单个云函数 ≤150 行（超过需拆分到 common/）
- 单个页面 ≤500 行（超过需拆分子组件）
- 单个组件 ≤200 行

当前已知接近边界：
- `getDashboardStats` 153 行（接近，可接受）
- `pages/index/index.vue` 559 行（首页，含较多 section，可接受但建议未来拆 NewsSection/NoticeSection 等子组件）
