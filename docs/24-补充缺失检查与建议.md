# 24 - 补充缺失检查与建议（修订版）

> 本文档反映 v1.1（2024-10 修订版）代码实际完成情况，与代码事实对齐。
> 本版修复了原审查报告中的 P0/P1 关键问题，详见 docs/27-修订更新日志.md

## 24.1 已修复的 P0 关键问题

### 24.1.1 status 中英文混用 → 全中文统一
- 14 处云函数（submitFeedback / dispatchRecord / handleSecretRecord / evaluateFeedback / updateFeedbackStatus / updateSnapshotStatus / submitSnapshot / getDashboardStats / sendOverdueReminder / getMeetingReviewList / generatePerformanceReport / exportPerformanceReport / generateUpperReport / getPerformanceDashboard / getFeedbackList / getMyFeedback / reviewContent / getSnapshotWall）全部使用 `cloudfunctions/common/constants.js` 中定义的中文常量
- 老英文数据通过 `expandStatuses()` 兼容读取，不会丢失历史数据
- 上线后调用一次 `migrateStatusEnum` 云函数即可把历史英文数据全部转为中文

### 24.1.2 type key 不匹配 → 全中文
- `store/config.js` feedbackTypes 改为中文 key（与 name 一致）
- `submitFeedback` 中 `dispatchMap[type]` 直接匹配中文，无 type key 不匹配
- `dispatch-config.vue` 改用 `configStore.feedbackTypes` 动态获取，不再硬编码

### 24.1.3 鉴权与安全
- `updateTaskProgress` 加 OPENID 鉴权（任务指派人 or 管理员）
- `approveUser` 防重复审核（校验 verifyStatus === '待审核'）
- `likeNews` / `likeSnapshot` 改用 `runTransaction` 防并发
- 9 个 admin/* 页面通过 `composables/useAdminGuard.js` 集中权限拦截
- `checkImageSecurity` 修复为先 `cloud.downloadFile` 再传 buffer
- `checkContentSecurity` 改为 fail-closed，并检查 `res.result.suggest`

### 24.1.4 内容安全全覆盖
所有 publish*/create* 云函数均接入内容安全：
- `publishNews` / `publishNotice` / `publishProject` / `publishFinanceReport` / `publishMarketPrice` / `publishTeamMember` / `publishBroadcast` / `publishTask` / `createVote` / `createMeeting`
- 原 `submitFeedback` / `submitSnapshot` / `submitSecretaryMail` / `publishLostFound` 已有

### 24.1.5 合规与审核
- `App.vue` 新增首次进入协议同意弹窗（onLaunch 时检查 agreementAgreed storage）
- 新增独立 `pages/privacy/index.vue` 隐私政策页（微信审核必需）
- 新增 `pages/report/index.vue` + `submitReport` 云函数 + `reports` 集合的举报机制
- `mine.vue` 增加隐私政策菜单项
- `verify.vue` 协议勾选同时引用"服务协议"和"隐私政策"两个页面
- `sitemap.json` 改为白名单制，admin/auth/secretary/feedback/snapshot 等内部页禁止索引

## 24.2 已修复的 P1 高优先级问题

### 24.2.1 死代码清理
- `store/user.js` 删除调用不存在的 `checkAdmin` 云函数的 `checkAdmin()` 方法
- `utils/request.js` 删除调用不存在的 `getOpenid` 云函数的 `getOpenid()` 方法

### 24.2.2 防重复提交
- `acquireLock` 改为 try/finally 模式，成功路径也释放锁
- `feedback.vue` / `snapshot.vue` / `mailbox.vue` / `verify.vue` / `publish.vue` 全部接入

### 24.2.3 表单草稿
- `feedback` / `snapshot` / `mailbox` / `verify` 表单自动保存草稿到 storage，提交成功后清除
- `verify` 不保存身份证号到草稿（安全考量）

### 24.2.4 上传图片
- `uploadImages` 改为 3 并发上传（提速 3-5 倍）
- 增加进度回调 `onProgress(done, total)`
- 增加失败计数返回 `{ fileIDs, failed }`
- 新增 `cleanupFileIDs` 函数，失败时清理孤儿文件
- `compressImage` 小图（< 1080px）跳过压缩

### 24.2.5 首页与详情
- `getHomeData` 5 个并发查询每个加 `.catch` 降级，单个失败不影响整体
- `news/detail.vue` 加错误态 + 重试按钮 + 举报入口
- 列表 image 加 `lazy-load`

### 24.2.6 mine.vue 升级
- 替换已废弃的 `wx.getUserProfile`（2022.10 起只返回匿名昵称）
- 改用 `button open-type="chooseAvatar"` + `input type="nickname"`
- 默认头像改为 base64 PNG（替代 SVG，兼容性更好）
- ICP 备案号从 `module_config.village_info` 动态读取
- 防止微信"微信用户"匿名昵称覆盖已有真实昵称

### 24.2.7 看板优化
- `dashboard.vue` 月份选择器从 `['本月','上月','本月']` 改为动态生成最近 12 个月
- tab 切换 300ms 防抖，连续点击 5 次只执行最后一次

### 24.2.8 admin/publish 优化
- 切换类型用 `Object.assign(form, createForm())` 全量重置，避免残留垃圾字段
- 接入 VoiceInput 语音输入
- acquireLock + cleanupFileIDs 失败清理

### 24.2.9 网络与错误处理
- `callFunction` 加 15s 客户端超时保护
- `App.vue` 加 `onError` / `onUnhandledRejection` / `onPageNotFound` 全局错误捕获
- `App.vue` 加 `onNetworkStatusChange` 网络状态监听，断网 toast 提示
- 新增 `logError` 云函数接收前端错误日志上报

### 24.2.10 配置驱动化
- `sendSubscribeMessage` 模板 ID 从 `module_config.subscribe_templates` 动态加载（5 分钟实例级缓存）
- 模板未配置时跳过 + 记录日志，不阻断业务
- `store/config.js` 紧急电话从云端 module_config 加载（默认仅 110/120/119）

## 24.4 上线前操作步骤（按顺序）

1. **替换占位符**（24.3 清单）
2. **部署云函数**：80 个云函数（含新增 submitReport / migrateStatusEnum / logError）
   - 部署顺序：`common/checkAdmin` 和 `common/constants` 不需要部署（仅 require）
   - 先部署依赖：`initDatabase` 初始化数据库
   - 再部署业务云函数
   - 最后部署定时触发器（按 docs/07 配置）
3. **运行数据迁移**：在云开发控制台手动调用 `migrateStatusEnum` 云函数一次（dryRun 模式先试运行，确认无问题后正式执行）
4. **配置 module_config**：
   - 添加 `moduleKey: 'village_info'` 配置（含 villageName / villagePhone / emergencyPhones / icpNumber / policeIcpNumber）
   - 添加 `moduleKey: 'subscribe_templates'` 配置（7 个订阅消息模板 ID）
   - 添加 `moduleKey: 'feedback'` 配置 dispatchMap（各类型责任人）
5. **添加管理员**：在 `admins` 集合添加 `{ _openid, enabled: true }` 记录
6. **申请订阅消息模板**：按 docs/14 在微信公众平台申请 7 个模板
7. **配置 ASR**（可选）：按 docs/15 配置百度 ASR API Key
8. **配置内容安全接口**：按 docs/16 开通 msgSecCheck/imgSecCheck 权限
9. **提交审核**：按 docs/17 预检清单通过后提交微信审核
