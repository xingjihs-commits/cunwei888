# 第十八部分：线上应急预案

**适用对象**：村文书、村支书、技术对接人
**目的**：线上故障时快速响应，减少影响

---

## 18.1 云函数报错处理

### 18.1.1 常见报错类型

| 报错类型 | 现象 | 原因 | 处理方法 |
|---------|------|------|---------|
| 超时 | "Function timed out" | 执行时间超10秒 | 1.优化代码；2.拆分云函数；3.增加超时配置 |
| 内存溢出 | "Memory limit exceeded" | 内存超256MB | 1.减少返回数据量；2.分批处理 |
| 依赖缺失 | "Cannot find module" | package.json未安装依赖 | 1.检查package.json；2.重新部署 |
| 环境变量未配置 | "process.env.XXX is undefined" | 环境变量未设置 | 1.云开发控制台→环境变量；2.添加变量 |
| 数据库权限 | "permission denied" | 安全规则限制 | 1.检查集合安全规则；2.用云函数管理员SDK |
| 调用频率超限 | "rate limit exceeded" | 频率过高 | 1.降低调用频率；2.优化代码 |

### 18.1.2 如何查看云函数日志

1. 微信开发者工具→云开发控制台→云函数
2. 选择报错的云函数
3. 点击「日志」标签
4. 查看错误详情、调用时间、错误码

### 18.1.3 如何快速回滚

1. 云开发控制台→云函数→版本管理
2. 找到上一个稳定版本
3. 点击「回滚」
4. 确认回滚
5. 即时生效

### 18.1.4 联系微信云开发支持

|------|---------|---------|
| 腾讯云客服 | 95716（7×24） | 云开发环境问题 |
| 微信公众平台 | 95173117（7×24） | 小程序问题 |

## 18.2 数据不显示处理

### 18.2.1 数据库权限问题排查

| 现象 | 排查步骤 |
|------|---------|
| 列表为空 | 1.云开发控制台→数据库→检查集合是否有数据；2.检查安全规则是否允许读取 |
| 提示"无权查看" | 1.检查用户是否实名认证；2.检查安全规则；3.检查是否用云函数调用（绕过安全规则） |

### 18.2.2 环境ID配置问题排查

| 现象 | 排查步骤 |
|------|---------|
| 全部页面白屏 | 1.检查App.vue的env配置；2.确认云开发环境已开通；3.确认AppID与环境绑定 |
| 提示"环境不存在" | 1.云开发控制台→设置→环境ID；2.对比App.vue中的env |

### 18.2.3 网络问题排查

| 现象 | 排查步骤 |
|------|---------|
| 加载缓慢 | 1.检查网络信号；2.切换WiFi/4G；3.检查云函数冷启动 |
| 提示网络错误 | 1.重启微信；2.清除缓存；3.检查手机系统时间 |

### 18.2.4 缓存问题排查

| 现象 | 排查步骤 |
|------|---------|
| 数据不更新 | 1.下拉刷新；2.清除缓存（「我的」→「个人信息」→「清除缓存」）；3.重启小程序 |

## 18.3 订阅消息收不到处理

### 18.3.1 模板ID错误排查

| 排查步骤 | 操作 |
|---------|------|
| 1.检查模板ID | cloudfunctions/sendSubscribeMessage/index.js→TEMPLATES对象 |
| 2.对比公众平台 | 微信公众平台→订阅消息→我的模板→对比模板ID |
| 3.重新部署 | 修改模板ID后重新部署sendSubscribeMessage云函数 |

### 18.3.2 用户未授权排查

| 排查步骤 | 操作 |
|---------|------|
| 1.检查用户授权 | 微信→我→设置→消息通知→订阅消息→村务连心桥 |
| 2.引导重新授权 | 在小程序内调用wx.requestSubscribeMessage |
| 3.检查是否被ban | 用户多次拒绝后会被ban，需wx.openSetting引导 |

### 18.3.3 发送频率超限排查

| 排查步骤 | 操作 |
|---------|------|
| 1.检查发送频率 | 控制每日发送次数≤3条/用户 |
| 2.检查触发器频率 | sendOverdueReminder每天1次（8点） |
| 3.优化发送逻辑 | 同类消息合并，避免重复发送 |

### 18.3.4 参数格式错误排查

| 排查步骤 | 操作 |
|---------|------|
| 1.检查关键词类型 | thing/phrase/time/number/amount等 |
| 2.检查参数值 | 不超过关键词长度限制（thing≤20字） |
| 3.云函数日志 | 查看sendSubscribeMessage云函数日志 |

## 18.5 上级检查准备

### 18.5.1 数据导出流程

1. 调用generateUpperReport云函数生成月度报表
2. 调用exportPerformanceReport导出CSV
3. 云开发控制台→数据库→导出关键集合JSON
4. 整理为汇报材料

### 18.5.2 汇报材料准备

| 材料 | 内容 | 准备时限 |
|------|------|---------|
| 平台运营情况 | 注册数/活跃数/工单数/满意度 | 检查前1天 |
| 内容公示情况 | 新闻数/公示数/广播数 | 检查前1天 |
| 财务三资公示 | 季度财务报表 | 检查前1周 |
| 考核统计数据 | 责任人排行+超时明细 | 检查前1天 |
| 对上汇报数据 | 月度汇报5大块 | 检查前1天 |

### 18.5.3 演示流程

1. 打开小程序首页，展示书记直达+新闻
2. 演示村民反映提交流程
3. 演示随手拍公示墙
4. 展示信息公示（财务重点）
5. 展示考核看板+对上汇报
6. 展示书记信箱+广播

### 18.5.4 常见问题应答

| 问题 | 答案要点 |
|------|---------|
| "用户数多少？" | 注册XX人，活跃XX人，活跃率XX% |
| "工单处理时效？" | 平均X天，按时办结率XX% |
| "财务公示频率？" | 每季度1次，含收支资产负债 |
| "如何保护隐私？" | 实名认证+安全规则+内容安全检测 |
| "如何对上汇报？" | 一键生成月度报表，含5大块数据 |

## 18.6 云开发欠费/到期处理

### 18.6.1 如何续费

1. 微信开发者工具→云开发控制台→设置→套餐管理
2. 选择续费套餐（建议基础版，19.9元/月）
3. 微信支付
4. 续费完成

### 18.6.2 如何备份数据

**欠费前**：
1. 每月1日导出全部数据（见《04-数据备份与换届交接制度.md》）
2. 备份到云盘+本地电脑+光盘

**欠费后**：
1. 立即续费
2. 如数据已删除，从备份恢复
3. 云开发控制台→数据库→导入JSON

### 18.6.3 欠费后数据保留多久

| 情况 | 数据保留 |
|------|---------|
| 欠费1-7天 | 数据保留，服务暂停 |
| 欠费8-30天 | 数据保留，需续费才能访问 |
| 欠费超30天 | 数据可能被清理，需联系客服 |

### 18.6.4 到期前预警提醒

- 到期前7天：微信公众平台短信提醒
- 到期前3天：管理员邮箱提醒
- 到期前1天：管理员微信号提醒
- 建议设置自动续费，避免忘记

## 18.8 系统故障分级

### 18.8.1 一级故障（全站不可用）

| 项目 | 标准 |
|------|------|
| 现象 | 小程序完全无法打开/全部功能不可用 |
| 响应时间 | 立即响应（5分钟内） |
| 处理时限 | 2小时内恢复 |
| 处理流程 | 1.排查云开发环境；2.联系腾讯云客服；3.启用备用方案；4.通知村民；5.上报街道办 |
| 通知范围 | 全村村民+上级街道办 |

### 18.8.2 二级故障（部分功能不可用）

| 项目 | 标准 |
|------|------|
| 现象 | 部分页面/功能不可用（如工单提交失败） |
| 响应时间 | 30分钟内 |
| 处理时限 | 4小时内恢复 |
| 处理流程 | 1.排查对应云函数；2.检查数据库；3.修复并重新部署；4.通知村文书 |
| 通知范围 | 受影响村民+村文书 |

### 18.8.3 三级故障（体验问题）

| 项目 | 标准 |
|------|------|
| 现象 | 功能可用但体验差（如加载慢、样式错乱） |
| 响应时间 | 24小时内 |
| 处理时限 | 3天内修复 |
| 处理流程 | 1.记录问题；2.排期修复；3.下次版本更新 |
| 通知范围 | 村文书 |

### 18.8.4 各级故障处理流程对比

| 故障级别 | 响应时间 | 处理时限 | 通知范围 | 升级条件 |
|---------|---------|---------|---------|---------|
| 一级 | 5分钟 | 2小时 | 全村+街道办 | 自动升级街道办 |
| 二级 | 30分钟 | 4小时 | 受影响村民+文书 | 4小时未恢复升级一级 |
| 三级 | 24小时 | 3天 | 文书 | 3天未修复升级二级 |
